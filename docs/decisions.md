# Решения по неоднозначностям ТЗ

ТЗ оставляет много места для толкования. До начала работы агент составил список из 22 неоднозначных мест, каждое разобрано с человеком. Ниже — итог.

## Роли

| Вопрос | Решение |
|---|---|
| Как креативщик получает задачу | Общий пул: задачу берёт тот, кто первым нажал «Взять». Байер исполнителя не назначает |
| Права руководителя | Всё, что может байер, плюс снять или переназначить исполнителя, управлять пользователями и справочником AI-сервисов |
| Несколько ролей у пользователя | Да; права — объединение прав ролей. Свою задачу взять нельзя, проверять свою работу нельзя |
| Регистрация | Нет: тестовые пользователи из сида, новых заводит руководитель |

## Задача

| Вопрос | Решение |
|---|---|
| «Количество» | Одна задача на N креативов, один исполнитель |
| Референсы и результат | Ссылки и файлы до 20 МБ (изображения, видео, PDF), тип — по содержимому файла |
| Приоритет | 4 уровня: низкий / обычный / высокий / срочный; сортировка колонки «приоритет → дедлайн» |
| Дедлайн | Необязательный. Без него — диалог с последствиями (не попадёт в просрочки и т.д.) |
| Редактирование | В любом статусе до «Готово»; каждое изменение — в историю; у исполнителя пометка «ТЗ изменено» |
| Удаление | Нет. Есть «Отменить» с причиной: задача уходит в архив, история и расходы сохраняются |

## Статусы и время

| Вопрос | Решение |
|---|---|
| После «На правки» | Исполнитель сразу «Сдаёт исправленное»; правки делает тот же исполнитель |
| Время выполнения | **Чистое время креативщика**: сумма отрезков «взял → сдал» и «отправили на правки → сдал исправленное». Ожидание проверки не считается |
| Просрочка | По **первой сдаче**. Не сдана и дедлайн прошёл — текущая просрочка. Перенос дедлайна после сдачи опоздание не стирает |

## AI-расходы

| Вопрос | Решение |
|---|---|
| Список сервисов | Строгий справочник, ведёт руководитель; отключение вместо удаления |
| Кредиты | Дробные (2 знака), только кредиты, итоги по каждому сервису отдельно — без общей суммы (кредиты разных сервисов несопоставимы) |
| Когда вносить | В любой момент, без привязки к этапу; исполнитель — до закрытия задачи, руководитель — всегда |

## Аналитика

| Вопрос | Решение |
|---|---|
| Загрузка | Активные задачи и креативы по статусам + завершённые за период |
| Период | «Сегодня / Неделя / Месяц / Квартал» + произвольный диапазон, по умолчанию текущий месяц; фильтры по байеру, креативщику, офферу |
| Привязка к периоду | Созданные — по дате создания; завершённые и время — по дате принятия; просрочки — по дедлайну; расходы — по дате записи |

## Демо и качество

| Вопрос | Решение |
|---|---|
| Хостинг | Свой VPS, Docker Compose, HTTPS (nginx + Let's Encrypt) |
| Вход | Кнопки тестовых пользователей + обычная форма; ночной сброс демо-данных |
| Обновление доски | Опрос раз в 12 секунд и при возврате на вкладку |
| Язык | Только русский |
| Тесты | Backend (pytest), frontend unit (Vitest), сквозные e2e (Playwright), CI |

## Машина состояний

| Из | В | Кто | Действие |
|---|---|---|---|
| Новые | В работе | креативщик (не автор) | Взять |
| В работе / Правки | На проверке | исполнитель, с результатом текущей версии | Сдать / Сдать исправленное |
| На проверке | Готово | автор или руководитель (не исполнитель) | Принять |
| На проверке | Правки | автор или руководитель (не исполнитель), с комментарием | На правки |
| любой открытый | Отменена | автор или руководитель, с причиной | Отменить |
| В работе / На проверке / Правки | тот же | руководитель | Сменить исполнителя |
| В работе / Правки | Новые | руководитель | Вернуть в пул |

Правила доступа описаны в одном модуле backend (`app/services/task_permissions.py`): он и проверяет каждое действие, и отдаёт клиенту список доступных действий — фронт рисует кнопки и разрешает drag-and-drop только по нему.
