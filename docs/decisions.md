# Решения по неоднозначностям ТЗ

ТЗ оставляет много места для толкования. До начала работы агент составил список из 22 неоднозначных мест, каждое разобрано с человеком. Решения, принятые по ходу работы (перенос руководителем, вкладки аналитики, сдача без материала и др.), добавлены в те же разделы. Ниже — итог.

## Роли

| Вопрос | Решение |
|---|---|
| Как креативщик получает задачу | Общий пул: задачу берёт тот, кто первым нажал «Взять». Байер исполнителя не назначает. Руководитель может сам назначить исполнителя на новую задачу — кнопкой в карточке или переносом в «В работе» с выбором креативщика; задача сразу уходит в работу, время идёт с момента назначения |
| Права руководителя | Всё, что может байер, плюс назначить, снять или переназначить исполнителя, переносить любую карточку в любую колонку доски, управлять пользователями и справочником AI-сервисов |
| Перенос руководителем | Из любой колонки в любую (отмена — только кнопкой с причиной). Штатный переход, если он есть (принять, на правки, вернуть в пул), выполняется как обычно; иначе — принудительный перенос: из «Новых» — с выбором исполнителя, в «Правки» — с комментарием, на проверку и в «Готово» — без результата, но не свою работу (если руководитель сам исполнитель). В аналитике всё засчитывается исполнителю (ответственному), а не руководителю: время работы, сдача и просрочка, завершение. В истории — отдельное событие «Руководитель перенёс задачу» |
| Несколько ролей у пользователя | Да; права — объединение прав ролей. Свою задачу взять нельзя, проверять свою работу нельзя |
| Регистрация | Нет: тестовые пользователи из сида, новых заводит руководитель |

## Задача

| Вопрос | Решение |
|---|---|
| «Количество» | Одна задача на N креативов, один исполнитель |
| Референсы и результат | Ссылки и файлы до 20 МБ (изображения, видео, PDF), тип — по содержимому файла |
| Приоритет | 4 уровня: низкий / обычный / высокий / срочный; сортировка колонки «приоритет → дедлайн»; в «Готово» — по дате принятия, свежие сверху |
| Дедлайн | Необязательный. Без него — диалог с последствиями (не попадёт в просрочки и т.д.) |
| Редактирование | В любом статусе до «Готово»; каждое изменение — в историю; у исполнителя пометка «ТЗ изменено» |
| Удаление | Нет. Есть «Отменить» с причиной: задача уходит в архив, история и расходы сохраняются |

## Статусы и время

| Вопрос | Решение |
|---|---|
| После «На правки» | Исполнитель сразу «Сдаёт исправленное»; правки делает тот же исполнитель |
| Возврат из «Готово» | Только руководитель, с комментарием: задача уходит тому же исполнителю новым кругом правок, дата завершения снимается (в аналитике задача снова не завершена до повторного принятия). Просрочка по первой сдаче не меняется |
| Возврат в пул с проверки | Только руководитель. Сданный результат остаётся в истории, но новому исполнителю не засчитывается — для сдачи нужен свой результат |
| Время выполнения | **Чистое время креативщика**: сумма отрезков «взял → сдал» и «отправили на правки → сдал исправленное». Ожидание проверки не считается |
| Просрочка | По **первой сдаче**. Не сдана и дедлайн прошёл — текущая просрочка. Перенос дедлайна после сдачи опоздание не стирает |

## AI-расходы

| Вопрос | Решение |
|---|---|
| Список сервисов | Строгий справочник, ведёт руководитель; отключение вместо удаления |
| Кредиты | Дробные (2 знака), только кредиты, итоги по каждому сервису отдельно — без общей суммы (кредиты разных сервисов несопоставимы). Единственное исключение — общая доля кредитов на правки в процентах, рядом с долей по каждому сервису |
| Первая версия и правки | Каждый расход запоминает круг правок на момент внесения: 0 — первая версия, 1, 2… — правки. Изменение записи круг не меняет. Старые записи разложены по кругам по истории задачи (миграция) |
| Когда вносить | В любой момент, без привязки к этапу; исполнитель — до закрытия задачи, руководитель — в любой задаче с исполнителем, в том числе закрытой. Расход всегда записывается на исполнителя задачи; в «Новых» (исполнителя нет) расходы не вносятся |

## Аналитика

| Вопрос | Решение |
|---|---|
| Загрузка | Активные задачи и креативы по статусам + завершённые за период |
| Период | «Сегодня / Неделя / Месяц / Квартал» + произвольный диапазон, по умолчанию текущий месяц; фильтры по байеру, креативщику, офферу |
| Вкладки | «Пользователи и задачи», «Учёт AI-расходов», «Учёт времени»; фильтры общие, каждая вкладка грузит только свои данные (`/api/analytics/overview`, `/ai`, `/time`) |
| Привязка к периоду | Созданные — по дате создания; «Задачи по статусам» — созданные в периоде, по текущему статусу; завершённые, время работы, ожидание в пуле и на проверке — по дате принятия; отменённые — по дате отмены; просрочки — по дедлайну; расходы — по дате записи |
| Ожидание проверки | Сумма отрезков «На проверке» по истории задачи; засчитывается тому, кто фактически принял работу (последний переход в «Готово»). «Сейчас ждут проверки» — на текущий момент, без периода |
| Ожидание в пуле | Сумма отрезков «Новые», включая возвраты в пул |
| Фильтр креативщика на вкладке «Учёт времени» | Задачи, где он исполнитель, и задачи, над которыми он работал до переназначения — иначе его время пропадало бы из строки «По креативщикам» при включённом фильтре |

## Демо и качество

| Вопрос | Решение |
|---|---|
| Хостинг | Свой VPS, Docker Compose, HTTPS (nginx + Let's Encrypt) |
| Вход | Обычная форма; тестовые логины — в README. Кнопки быстрого входа есть за флагом `APP_DEMO_MODE`, но выключены: публичный список пользователей на экране входа — неправильный сигнал для сервиса. Ночной сброс демо-данных |
| Обновление доски | Опрос раз в 12 секунд и при возврате на вкладку |
| Язык | Только русский |
| Тесты | Backend (pytest), frontend unit (Vitest), сквозные e2e (Playwright), CI |

## Машина состояний

| Из | В | Кто | Действие |
|---|---|---|---|
| Новые | В работе | креативщик (не автор) | Взять |
| Новые | В работе | руководитель; исполнитель — активный креативщик, не автор | Назначить исполнителя |
| В работе / Правки | На проверке | исполнитель, с результатом текущей версии или с подтверждением галочкой «Сдать без материала» (отмечается в истории) | Сдать / Сдать исправленное |
| На проверке | Готово | автор или руководитель (не исполнитель) | Принять |
| На проверке | Правки | автор или руководитель (не исполнитель), с комментарием | На правки |
| Готово | Правки | руководитель (не исполнитель), с комментарием | Вернуть на правки |
| любой открытый | Отменена | автор или руководитель, с причиной | Отменить |
| В работе / На проверке / Правки | тот же | руководитель | Сменить исполнителя |
| В работе / На проверке / Правки | Новые | руководитель | Вернуть в пул |
| любой, кроме «Отменена» | любая другая колонка доски | руководитель; из «Новых» — с выбором исполнителя | Перенос (если нет штатного перехода) |

Правила доступа описаны в одном модуле backend (`app/services/task_permissions.py`): он и проверяет каждое действие, и отдаёт клиенту список доступных действий — фронт рисует кнопки и разрешает drag-and-drop только по нему.
