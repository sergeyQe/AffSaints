# Креативный отдел — руководство для проверки

Мини-сервис управления креативным отделом: байеры ставят ТЗ, креативщики берут задачи и сдают работу, руководитель видит загрузку, сроки, время и расходы AI-кредитов.

## Как устроен сервис — за минуту

```
            байер создаёт ТЗ
                  │
                  ▼
 ┌────────┐  Взять  ┌──────────┐  Сдать  ┌─────────────┐ Принять ┌────────┐
 │ Новые  │ ──────► │ В работе │ ──────► │ На проверке │ ──────► │ Готово │
 └────────┘         └──────────┘         └─────────────┘         └────────┘
                                          ▲          │                │
                          Сдать исправл.  │          │ На правки      │ Вернуть на правки
                                          │          ▼ (с коммент.)   │ (руководитель)
                                         ┌────────────┐               │
                                         │   Правки   │ ◄─────────────┘
                                         └────────────┘
```

- **Байер** создаёт ТЗ — задача появляется в колонке «Новые», в общем пуле.
- **Креативщик** сам берёт задачу из пула («Взять в работу»), прикладывает результат (ссылку или файл) и сдаёт на проверку.
- **Байер** принимает работу («Готово») или отправляет на правки с комментарием. Правки делает тот же креативщик и сдаёт исправленное — это новый «круг правок».
- **Руководитель** видит всё, может назначать и снимать исполнителей, переносить любые карточки и смотрит аналитику.

Сервис сам фиксирует время каждого шага, считает чистое время работы и ведёт полную историю действий.

## Сценарий проверки (~15 минут)

Каждый шаг привязан к пункту задания.

### 1. Постановка ТЗ — `anna`

1. Войти как `anna` → кнопка **«Новое ТЗ»**.
2. Заполнить форму: оффер, GEO, тип креатива, количество, описание, референс (ссылка или файл), приоритет, дедлайн.
   - Дедлайн ставится календарём или кнопками **«−1 час / −1 день / −1 неделя»** и **«+1 час / +1 день / +1 неделя»** — каждое нажатие сдвигает текущее значение.
   - Без дедлайна сервис предупредит о последствиях (задача не попадёт в учёт просрочек).
3. **«Создать задачу»** — карточка появится в колонке «Новые».

> ТЗ: *«байер создаёт ТЗ через форму (оффер, GEO, тип креатива, количество, описание, референсы, приоритет, дедлайн)»*.

Если закрыть форму, не создав задачу, введённое не пропадёт: при следующем «Новое ТЗ» форма откроется уже заполненной, с пометкой «Восстановлен черновик». Черновик хранится 30 минут с последнего изменения, у каждого пользователя свой; файлы-референсы в нём не сохраняются — их нужно приложить заново. Кнопка «Сбросить черновик» очищает форму.

### 2. Взять задачу и сдать работу — `ivan`

1. Войти как `ivan`. Новая задача видна на доске.
2. Взять её: кнопкой **«Взять в работу»** в карточке или **перетащить** карточку в колонку «В работе».
3. Вкладка **«Файлы»** → приложить результат (ссылка или файл до 20 МБ).
4. Вкладка **«AI-расходы»** → выбрать сервис, указать кредиты → «Добавить». У записи появится метка **«Первая версия»**.
5. **«Сдать на проверку»** (или перетащить в «На проверке»).
   - Если результат не приложен, откроется окно «Материал не приложен»: можно приложить материал или явно сдать без него, поставив галочку (по умолчанию она выключена). Сдача без материала отмечается в истории.

> ТЗ: *«креативщик самостоятельно берёт задачу, прикрепляет результат»*, *«учёт AI-расходов»*.

### 3. Отправить на правки — `anna`

1. Войти как `anna`, открыть задачу в колонке «На проверке», посмотреть результат во вкладке «Файлы».
2. **«На правки»** → написать, что исправить → «Отправить на правки».

> ТЗ: *«байер принимает работу или отправляет на правки»*.

### 4. Правки — `ivan`

1. Комментарий байера виден в карточке.
2. Внести ещё один AI-расход — у него будет метка **«Правки №1»** (так видно, сколько кредитов ушло на первую версию, а сколько — на правки).
3. Приложить новую версию результата («Версия 2») → **«Сдать исправленное»**.

> ТЗ: *«креативщик указывает … количество потраченных кредитов по каждой задаче, включая правки»*.

### 5. Принять работу — `anna`

**«Принять»** — задача уходит в «Готово». Открыть вкладки карточки:
- **«Детали»** — время создания, взятия в работу, первой и последней сдачи, завершения; чистое время работы; число кругов правок.
- **«История»** — каждое действие по порядку: кто, что и когда сделал, комментарии правок, изменения ТЗ, расходы.

> ТЗ: *«учёт времени: автоматически фиксируются время создания, взятия в работу, сдачи и завершения задачи, рассчитывается продолжительность выполнения»*, *«сохранение истории действий и изменения статусов»*.

### 6. Аналитика — `head`

Войти как `head` → **«Аналитика»**. Сверху — общие фильтры: период (Сегодня / Неделя / Месяц / Квартал / произвольный), байер, креативщик, оффер. Чтобы увидеть только свою тестовую задачу — введите её оффер в фильтр.

| Вкладка | Что показывает |
|---|---|
| **Пользователи и задачи** | Создано / завершено / отменено, в работе и просрочено сейчас, правок на задачу; динамика по дням; задачи по статусам; загрузка креативщиков |
| **Учёт AI-расходов** | Кредиты по сервисам, исполнителям и задачам с разбивкой «первая версия / правки»; доля кредитов на правки — общая и по каждому сервису |
| **Учёт времени** | Среднее время первой версии и правок; ожидание проверки и ожидание в пуле; таблицы по креативщикам и по задачам; блок «Сроки» — вовремя / с опозданием / не сдано / просрочено сейчас |

> ТЗ: *«руководитель видит количество задач, загрузку сотрудников, среднее время выполнения, просрочки и расходы AI-кредитов по сервисам и исполнителям»*.

### 7. Телефон

Сервис адаптирован под телефон (проверено на ширине 390 px): доска листается по колонкам, карточку можно перетащить пальцем (нажать и удерживать), фильтры доски спрятаны под кнопку «Фильтры», форма ТЗ и карточка открываются на весь экран, аналитика — с короткими вкладками «Задачи / AI-расходы / Время».

## Логика работы — подробнее

### Роли и права

| Действие | Байер | Креативщик | Руководитель |
|---|---|---|---|
| Создать ТЗ | ✅ | — | ✅ |
| Редактировать и отменить ТЗ (до «Готово») | свои | — | любые |
| Взять задачу из пула | — | ✅ (не свою) | — |
| Приложить результат, сдать | — | исполнитель задачи | — |
| Принять / отправить на правки | автор задачи | — | ✅ |
| Вернуть принятую работу на правки | — | — | ✅ |
| Назначить, сменить, снять исполнителя | — | — | ✅ |
| Перенести карточку в любую колонку | — | — | ✅ |
| Внести AI-расходы | — | исполнитель, до закрытия задачи | в любой задаче, где есть исполнитель (и после закрытия) |
| Аналитика, пользователи, справочник AI-сервисов | — | — | ✅ |

- У пользователя может быть несколько ролей — права складываются (`kate` — байер и креативщик).
- Свою задачу взять нельзя, свою работу проверять нельзя.
- Права проверяет сервер. Интерфейс показывает только доступные кнопки и разрешает перетаскивать карточки только туда, куда можно: при переносе подходящие колонки подсвечиваются **зелёным**, недоступные — **красным**.

### Доска

- Колонки: **Новые → В работе → На проверке → Правки → Готово**. В колонке «Готово» — задачи, завершённые за последние 30 дней. Все завершённые (без ограничения по сроку) и отменённые задачи — в разделе «Архив».
- В колонке задачи отсортированы по приоритету (срочные выше), затем по дедлайну. В «Готово» — по дате принятия, свежие сверху.
- На карточке видны приоритет, просрочка, число кругов правок, исполнитель и пометка «ТЗ изменено», если байер поправил ТЗ после взятия.
- Фильтры: оффер, GEO, исполнитель, байер, приоритет, «Только просроченные». Переключатель **«Доступные только мне»** (включён по умолчанию) оставляет задачи, с которыми у пользователя есть действие, и его собственные.
- Доска обновляется автоматически каждые 12 секунд и при возврате на вкладку браузера.
- Если одну задачу одновременно пытаются взять двое креативщиков, она достанется первому, второй получит понятное сообщение.

### Возможности руководителя

- **Назначить исполнителя** на новую задачу (кнопкой или переносом в «В работе» с выбором креативщика).
- **Сменить исполнителя** или **вернуть задачу в пул** — время прежнего исполнителя сохраняется за ним.
- **Вернуть принятую работу на правки** с комментарием — начнётся новый круг правок.
- **Перенести карточку в любую колонку**. Всё, что попадает в аналитику (время, сдача, просрочка, завершение), при этом засчитывается исполнителю, а не руководителю.

### Учёт времени

- Автоматически фиксируются: **создание, взятие в работу, первая и последняя сдача, завершение**.
- **Время работы — чистое время креативщика**: сумма отрезков «взял → сдал» и «отправили на правки → сдал исправленное». Время, пока работа ждёт проверки, не считается.
- При смене исполнителя время делится: каждому — его отрезки.

### Просрочки

- Просрочка считается **по первой сдаче**: сдана позже дедлайна — «с опозданием». Не сдана, а дедлайн прошёл — «просрочена сейчас».
- Перенос дедлайна после сдачи опоздание не стирает — сравнение идёт с дедлайном, действовавшим в момент сдачи.
- Задачи без дедлайна в учёт просрочек не попадают.

### AI-расходы

- Сервисы выбираются из справочника, который ведёт руководитель (отключённый сервис нельзя выбрать для новых записей, старые расходы по нему сохраняются).
- Кредиты дробные (до 2 знаков). Итоги — **отдельно по каждому сервису**: кредиты разных сервисов несопоставимы, поэтому общей суммы нет.
- Каждый расход запоминает круг: **«Первая версия»** или **«Правки №N»**. Отсюда в аналитике разбивка и доля кредитов на правки.
- Расход всегда записывается на исполнителя задачи — даже если его внёс руководитель. Пока у задачи нет исполнителя (в «Новых»), расходы не вносятся.

### Аналитика — к какой дате что относится

| Показатель | Привязка к периоду |
|---|---|
| Создано | по дате создания задачи |
| Задачи по статусам | задачи, созданные в периоде, — по их текущему статусу |
| Завершено, время работы, ожидание проверки и в пуле | по дате принятия |
| Отменено | по дате отмены |
| Просрочки | по дедлайну |
| AI-расходы | по дате записи расхода |
| В работе / просрочено / ждут проверки «сейчас» | на текущий момент, без периода |

- **Ожидание проверки** засчитывается тому, кто фактически принял работу.
- **Ожидание в пуле** — сколько задача пролежала в «Новых» до взятия, включая возвраты в пул.

### История

Каждое действие пишется в журнал задачи: создание, взятие, сдачи, правки с комментариями, приёмка, отмена с причиной, смена исполнителя, переносы руководителем, каждое изменение поля ТЗ (было → стало), файлы и AI-расходы. Удаления задач нет — вместо него «Отменить» с причиной: задача уходит в архив, история и расходы сохраняются.

- 7 пользователей (таблица выше).

## Что стоит знать

- Регистрации нет: пользователей заводит руководитель (раздел «Пользователи»).
- Интерфейс только на русском языке.
- Если на демо видны странные цифры (например, миллион кредитов в одной задаче) — это записи других проверяющих; утром демо сбросится.
